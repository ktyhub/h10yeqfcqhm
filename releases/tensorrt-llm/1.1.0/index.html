TensorRT-LLM v1.1.0

Highlights

  • Sampler switch is the one true breaking change — The C++ TRTLLM sampler is now enabled by default, replacing the legacy implementation (#6216). Sampling outputs, logprob shapes, and determinism may shift, so re-baseline accuracy and latency rather than assuming byte-identical behavior; if results regress after upgrading, this flag is the first thing to bisect.

  • uv sync installs fail out of the box — tensorrt-llm==1.1.0 pins patchelf==0.18.0, which was yanked upstream, so dependency resolution aborts on macOS/Python 3.13. The documented workaround is adding [tool.uv] override-dependencies = ["patchelf==0.17.2.4"]; CI using uv lockfiles needs the same override or it will refuse to resolve entirely.

  • New KV Cache Connector API reshapes disaggregated serving — A state-transfer API for KV handoff lands alongside MLA cache reuse, host-offloading examples, and KV cache salting for secure reuse (#6633, #6683). If you run prefill/decode disaggregation this is the migration path off ad-hoc transfer code; note KV cache events now carry attention DP rank info (#6563), so any event consumer must update its parsing.

  • Guided decoding now composes with speculative decoding — Constrained generation works with the two-model engine (#6300), CUDA graph padding plus draft-model chunked prefill (#6774), and disaggregated serving (#6704). That removes a long-standing “pick one” trade-off, but expands the CUDA-graph warmup surface that this release ships several fixes for (#6701, #6650) — stress-test OOM and padding handling with your own speculative configs.

  • New models and Blackwell/B300/GB300 hardware — GPT-OSS (#6645), Hunyuan Dense/MoE, Seed-OSS, and Eclairv2 (#6493) join the roster, with CuteDSL NVFP4 grouped GEMM and fused MoE kernels landing on Blackwell (#6616). Important caveat: GB300 multi-node is only beta and not fully validated in 1.1.0 — it was validated starting in 1.2.0rc4+, so avoid shipping multi-node GB300 on this release.

  • Base stack and API surface both moved — Images jump to pytorch:25.10-py3 / tritonserver:25.10-py3 with PyTorch 2.9.0, ModelOpt 0.37, transformers 4.56.0, xgrammar 0.1.25, NIXL 0.5.0, and cuda-python pinned to >=12,<13 (#6702). LLM arguments are now explicitly tagged stable vs. unstable and topk logprob returns are standardized across TRT and PyTorch backends — useful for pinning, but audit code that parsed the old logprob shape.

Know Issue

  • If users create project with tensorrt-llm==1.1.0 in pyproject.toml file as dependency as below:

    dependencies = [
  "tensorrt-llm==1.1.0",
]

    when users install project dependencies with command uv sync, error will happend with message:

    No solution found when resolving dependencies for split (markers: python_full_version >= '3.13' and sys_platform == 'darwin'):
╰─▶ Because patchelf==0.18.0.0 was yanked (reason: https://github.com/mayeut/patchelf-pypi/issues/87) and tensorrt-llm==1.1.0 depends on patchelf==0.18.0, we can
    conclude that tensorrt-llm==1.1.0 cannot be used.
    And because your project depends on tensorrt-llm==1.1.0, we can conclude that your project's requirements are unsatisfiable.".

    That’s because patchelf 0.18.0 was yanked by author.

    A valid work around for this issue is to add block in pyproject.toml:

    [tool.uv]
 override-dependencies = [
 "patchelf==0.17.2.4",
]

Key Features and Enhancements

  • Model Support
    • Add model supports of GPT-OSS, Hunyuan-Dense (contribution from @sorenwu), Hunyuan-MoE (contribution from @qianbiaoxiang), Seed-OSS (contribution from @Nekofish-Li).
  • Features
    • Connector API: Introduced a new KV Cache Connector API for state transfer in disaggregated serving.
    • Reuse & Offloading: Enabled KV cache reuse for MLA (Multi-Head Latent Attention) and added examples for host offloading.
    • Salting: Implemented KV cache salting for secure cache reuse.
    • Guided Decoding Integration: Enabled guided decoding to work in conjunction with speculative decoding (including 2-model and draft model chunked prefill).
    • Eagle: Added multi-layer Eagle support and optimizations.
    • CuteDSL: Integrated CuteDSL NVFP4 grouped GEMM for Blackwell.
    • B300/GB300: Added support for B300/GB300.
  • Documentation
    • Deployment Guides: Added comprehensive deployment guides for GPT-OSS, DeepSeek-R1, and VDR 1.0.
    • Feature Documentation: Created new documentation for KV Cache Connector, LoRA feature usage, and AutoDeploy.
    • Tech Blogs: Published blogs on “Combining Guided Decoding and Speculative Decoding” and “ADP Balance Strategy”.
    • Quick Start: Refined Quick Start guides with new links to ModelOpt checkpoints and updated installation steps (Linux/Windows).
    • API Reference: Enhanced LLM API documentation by explicitly labeling stable vs. unstable APIs.
    • Performance: Updated online benchmarking documentation and performance overview pages.
    • Examples: Refined Slurm examples and added K2 tool calling examples.
  • Infrastructure Changes
    • The base Docker image for TensorRT-LLM: nvcr.io/nvidia/pytorch:25.10-py3.
    • The base Docker image for TensorRT-LLM Backend: nvcr.io/nvidia/tritonserver:25.10-py3.
    • The dependent public PyTorch version: 2.9.0.
    • The dependent NVIDIA ModelOpt version: 0.37.
    • The dependent xgrammar version: 0.1.25.
    • The dependent transformers version: 4.56.0.
    • The dependent NIXL version: 0.5.0.
  • API Changes
    • Breaking Change: The C++ TRTLLM sampler is now enabled by default, replacing the legacy implementation.
    • KV Cache Connector API: Introduced a new KV Cache Connector API.
    • Standardized topk logprob returns across TRT and PyTorch backends.
    • Added stable labels to arguments in the LLM class to better indicate API stability.
    • Wait and Cancel API: Added tests and support for handling non-existent and completed request cancellations in the executor.
  • Fixed multiple Issues
  • illegal memory access, weight loading issues for DeepSeek-R1 W4A8, CUDA graph warmup issues with speculative decoding, memory leaks
  • Known Issues
    • GB300 Multi-Node: Support for GB300 in multi-node configurations is currently in beta and not fully validated in this release. GB300 multi-node configurations have been validated in 1.2.0rc4+.

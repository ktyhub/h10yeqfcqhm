LightRAG v1.4.9

patch PublishedSep 28, 2025 SourceHKUDS/LightRAG Chinese translation

LightRAG v1.4.9

Highlights

  • references on every query endpoint — All query APIs now return a references field containing cited documents and their identifiers (PR #2147). This is the release’s centerpiece: frontends can finally map an answer back to exact source chunks instead of scraping prose, which is the building block for auditable, citation-forward UIs on top of LightRAG.

  • Context format changed — audit your integrations — The context passed to the LLM was refactored and the streaming response now carries a references field (ignored by the frontend by default) (PR #2140). Any downstream code that parses the context data returned by the query API needs revisiting; treat this as a soft breaking change even though method signatures are unchanged.

  • Footnote citations you control — user_prompt now acts as an output instruction: ask for Markdown footnotes like [^1], and those numbers line up with document IDs in references. The WebUI renders footnote blocks in chat (PR #2145) and adds a saved-prompt dropdown in query settings (PR #2146), letting you wire answers directly to original source material in your own business system. Prompt examples are provided for GPT‑4.1‑mini/Qwen3 and DeepSeek.

  • File-deletion path traversal fixed — Deletion operations now validate against path traversal (PR #2113). If you expose file-management endpoints to untrusted input or multi-tenant users, this is the security fix that justifies upgrading.

  • Search and dedup behavior shifts — WebUI entity search moved from client-side to server-driven (PR #2124), and a comprehensive document-duplication prevention system landed (PR #2135). Expect different search latency and stricter handling of re-uploads; re-test automation that indexes the same document repeatedly.

  • Double-query bug eliminated — A dedicated aquery_llm path removes duplicate queries and standardizes response handling (PR #2152). Fewer redundant LLM calls means lower cost and latency on metered APIs for async/streaming queries.

Importance Notes

v1.4.9 introduces key enhancements focused on refining the reference output format and incorporating structured references into query results. All query API endpoints now include a references field, enabling frontend applications to retrieve cited documents and their corresponding identifiers associated with LightRAG query results.

The context format sent to the LLM has been updated. The streaming response from the LLM now includes a references field (ignored by the frontend by default). If your application relies on context data returned by the LightRAG query API, you may need to update your code accordingly.

By leveraging the user_prompt parameter, users can instruct the LLM to generate responses with footnote annotations. The footnote numbers in the LLM output can be seamlessly mapped to the document IDs returned in the references field. This integration enables tighter alignment between LightRAG and your business system, empowering users to access original source materials directly.

user_prompt act as additional output instruction for LLM. Here provide two examples:

  1. user_prompt for gpt-4.1-mini or Qwen3
For inline citations, employ the footnote reference format `[^1]`, where the `^` following the opening square bracket denotes a superscript link. When multiple citations are required at a single location, enclose each reference ID within separate footnote markers (e.g., `[^1][^2][^3]`).
  1. user_prompt for DeepSeek:
内嵌引文标注使用Markdown脚注格式`[^1]`, 当某处有多个引文标注时,应将每个引用ID分别置于独立的中括号内（例如：`[^1][^2][^3]`）。仅需对回答的关键事实和依据信息给出标注。出现在引文标中的引文ID都应该列在最后生成的参考文献中段落中。不要在参考文献段落之后生成脚注段落。

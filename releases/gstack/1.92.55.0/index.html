gstack v1.92.55.0

gstack v1.92.55.0

gstack v1.92.55.0 (regular release)

117 versions since v1.91.318.0, one line each. Compare or read the full changelog.

Team-mode installs follow the stable branch, which now points here; gstack-config set update_channel main follows every merge instead (docs/releases.md).

  • 1.92.55.0 (2026-11-02): /ship’s last step no longer stops a branch that lost its turn to merge, merged main and moved to the next version number; the version notes the branch wrote itself now count as bookkeeping, not a behavior change. (#3827)
  • 1.92.54.0 (2026-11-02): gstack-ship-queue can no longer publish two merges to main at the same time, and a PR missing its version bump can no longer merge. (#3737)
  • 1.92.53.0 (2026-11-02): The Ubicloud runner’s cleanup and startup now delete only your own VMs, never someone else’s in a shared project. (#3756)
  • 1.92.52.0 (2026-11-02): /ship on Capy runs its exploratory QA checks again. (#3686)
  • 1.92.50.0 (2026-11-01): /autoplan --ceo-only runs only the CEO review and asks no questions from start to finish. (#3788)
  • 1.92.49.0 (2026-11-01): The timeline Stop hook returns within its 2-second budget even when the host keeps stdin open. (#3715)
  • 1.92.48.0 (2026-11-01): On Windows, gstack-review-scope summary works again, and the JSONL merge driver no longer fails on non-English text or rewrites files with CRLF. (#3714)
  • 1.92.47.0 (2026-11-01): /ship runs its test jobs one at a time on machines with 4 or fewer CPU cores, so they no longer starve each other for memory, and a new flag picks serial or parallel by hand. (#3821)
  • 1.92.46.0 (2026-11-01): gstack-brain-sync no longer publishes a synced JSON file that doesn’t parse, and the profile and doctor say when one is broken. (#3796)
  • 1.92.45.0 (2026-11-01):
    • /ship’s review depth now follows risk, not diff size: code that touches security, user data, money, secrets, login or the merge checks gets the full review panel, other code gets a lighter review at any size, and docs, tests and write-ups get one reviewer. (#3820)
    • /ship runs at most two review rounds; a blocker still open after the second round stops and goes to the repository owner instead of starting a third. (#3820)
  • 1.92.44.0 (2026-11-01): /ship’s test selection no longer treats a sibling file with the same name as the changed module. (#3814)
  • 1.92.43.0 (2026-11-01): New page: docs/support-tiers.md says what gstack supports fully (macOS, Linux) and what it supports minimally (Windows, Gemini models). (#3812)
  • 1.92.42.0 (2026-11-01): A /ship review pass that left only notes now counts as a completed review. (#3694)
  • 1.92.41.0 (2026-11-01): The Ubicloud runner works on macOS and on a project with no VMs (#3680, #3679, #3678). (#3746)
  • 1.92.40.0 (2026-11-01): /ship run by a subagent now labels its reported cost as an upper bound. (#3696)
  • 1.92.38.0 (2026-11-01): gstack-brain-sync no longer gets stuck in push_failed when another machine changed a file you have edited locally. (#3728)
  • 1.92.37.0 (2026-11-01): /ship’s review no longer fails when a reviewer’s finding quotes text such as origin/<base> that looks like an unfilled template placeholder. (#3797)
  • 1.92.36.0 (2026-11-01): /ship’s review keeps every severity label again, so a blocker named after “no CRITICAL issues except” is no longer lost. (#3803)
  • 1.92.35.0 (2026-11-01): /ship’s test selection is fixed in three ways: a policy file that only raises the time limit no longer changes which tests are required, the “warn” setting no longer lets a failing test pass, and an empty test list no longer skips the suite of a deleted test. (#3792)
  • 1.92.34.0 (2026-11-01): When many PRs wait to merge, gstack-ship-queue wave plan groups them only by real code conflicts, so one busy docs file no longer chains dozens of unrelated PRs together, and PRs whose CI is red or still running are left out of the plan. (#3791)
  • 1.92.29.0 (2026-11-01):
    • /ship’s review no longer records a made-up blocker when a reviewer writes something like “found nothing CRITICAL”. (#3787)
    • Each finding /ship collects keeps the severity the reviewer actually wrote, and a follow-up issue for it shows that severity next to the collected label. (#3787)
  • 1.92.28.0 (2026-11-01): A PR that merges main and moves its changelog entry into changelog.d/ keeps its /ship review record. (#3706)
  • 1.92.27.0 (2026-11-01): /ship on Capy uses fewer tool calls: each step gets the instructions for the next step directly. (#3670)
  • 1.92.26.0 (2026-11-01): /retro shows which skills fought you this week: a “Friction by skill” row lists the top three skills by questions asked, errors and aborts in this project. (#3757)
  • 1.92.25.0 (2026-11-01): /ship stops with a clear message, listing any conflicted files, when an earlier merge, cherry-pick or revert is still unfinished, instead of starting another merge on top of it. (#3785)
  • 1.92.24.0 (2026-11-01): /ship can finish after the repository owner accepts a gap its documentation check flagged, and its final summary names who accepted it and when. (#3776)
  • 1.92.23.0 (2026-11-01): OpenClaw and Hermes users can turn on an optional start hook (gstack-harness register openclaw|hermes --start-hook) that reminds the agent on every turn to run a gstack skill’s start command as written; without it, agents in these tools ran that command 1 time in 29. It is off by default. (#3786)
  • 1.92.22.0 (2026-11-01): gstack installs into Gemini CLI, and installs made before v1.91.231.0 finally drop the test and eval packages they never needed. (#3778)
  • 1.92.20.0 (2026-11-01): /retro global now sees Kimi Code, OMP and Antigravity sessions (#2917, #1977). (#3740)
  • 1.92.19.0 (2026-11-01): On Linux and Windows, page rendering goes straight to gstack’s own browser instead of asking for Aside (#2864). (#3734)
  • 1.92.18.0 (2026-11-01): install.sh --project now resolves a subfolder to the top of its git repository, so settings declared in a subfolder no longer apply by accident, and it refuses a value that isn’t a folder, such as a repository name. (#3783)
  • 1.92.17.0 (2026-11-01): /ship’s reviewers now compare against the remote base branch, so a stale local copy of main no longer makes them review commits the branch only inherited. (#3780)
  • 1.92.16.0 (2026-11-01): /ship no longer runs a second review loop when only main moved, a test file changed, or the docs check’s own requested fix landed. (#3684)
  • 1.92.15.0 (2026-11-01):
    • Plan reviews check their facts: every file:line reference is opened, command flags are checked against --help, and the arithmetic behind a questioned number is written out. (#3775)
    • Rerunning a plan review keeps one task list, so /autoplan no longer drops an open task or shows a stale one. (#3775)
    • /office-hours saves the approved wireframe next to the design doc, and /plan-design-review rates the plan against that image. (#3775)
  • 1.92.14.0 (2026-11-01): A repository inside another repository can now be its own project: create an empty .gstack-project file in it. (#3777)
  • 1.92.13.0 (2026-11-01): /ship skips git merge when the base branch is already merged in, so it gets past its merge step on shared machines that block git merge. (#3774)
  • 1.92.12.0 (2026-11-01): When many PRs wait to merge, gstack-ship-queue wave can combine 3 to 6 PRs from one part of the code into one PR with one /ship run and one version. (#3772)
  • 1.92.11.0 (2026-11-01): /design-shotgun, /design-review, /plan-design-review and /design-html make image mockups with Google Gemini when no OpenAI key is set, instead of falling back to HTML wireframes; set GEMINI_API_KEY (a free key from Google AI Studio) to use it. (#3768)
  • 1.92.10.0 (2026-11-01): /ship’s focused second review runs again: its Red Team reads just the fix while the second-model reviewers still read the whole branch. (#3766)
  • 1.92.9.0 (2026-11-01): /freeze can no longer be walked around with paths through folders that don’t exist yet (#3623). (#3758)
  • 1.92.8.0 (2026-11-01): The secrets check no longer flags Python and Dart type names and variable reads as credentials (#3630). (#3742)
  • 1.92.7.0 (2026-11-01): /ship’s review step no longer crashes on very large diffs, where its review plan used to be cut off before it was fully read. (#3736)
  • 1.92.6.0 (2026-11-01): Choosing “core” for proactive suggestions now means the four core skills everywhere gstack suggests skills, and those skills list plain-English trigger phrases where agent tools read them. (#3770)
  • 1.92.5.0 (2026-10-31): Updates no longer stall in silence when the project around your gstack install has committed gstack’s files (#1022). (#3750)
  • 1.92.3.0 (2026-10-31): gstack-redact now catches a credential on a diff line. (#3726)
  • 1.92.2.0 (2026-10-31): gstack’s own model benchmarks now score each model with and without gstack side by side, using a paired judge that must pass calibration before it decides, and a results file is refused unless every arm has a row. (#3708)
  • 1.92.0.0 (2026-10-31): Batched merges (several ready PRs tested and merged together) now work for any repository, not just gstack. (#3692)
  • 1.91.379.0 (2026-10-31): /ship’s reviewers now review the checkout /ship ships, even when it runs from a worktree on a shared machine. (#3701)
  • 1.91.377.0 (2026-10-31): A passed GitHub Actions run can count as the remote test run for the same code, so a repository stops running its full suite twice per PR. (#3592)
  • 1.91.376.0 (2026-10-31): A remote test run on Ubicloud survives the local machine going to sleep: running the same command again reconnects to the live VM, and a long run split into tiers resumes from the tiers that already passed. (#3615)
  • 1.91.375.0 (2026-10-31): A /ship subagent stops once it reports the PR ready, so later CI and review events stop waking it. (#3597)
  • 1.91.374.0 (2026-10-31): /ship pauses when the base branch’s CI is red instead of failing. (#3611)
  • 1.91.373.0 (2026-10-31): /eval-plan requires every head-to-head preregistration to say whether any arm loads gstack, and when one does, to add a no-gstack arm per model with the same inputs and a plain prompt. (#3690)
  • 1.91.372.0 (2026-10-31): New gstack-flaky reruns a failed test command once; a pass no longer turns the CI job red, and each flake is recorded for a daily fix pass. (#3612)
  • 1.91.371.0 (2026-10-31): In a repository using batched merges, a PR push no longer waits ten minutes for a check that does no work. (#3609)
  • 1.91.369.0 (2026-10-31): gstack-wtree works again in a repository that gitignores .bun/. (#3685)
  • 1.91.368.0 (2026-10-31): /ship’s remote test run no longer dies at 300 seconds while it waits on CI. (#3682)
  • 1.91.367.0 (2026-10-31): /ship’s review no longer counts a reviewer that says it could not review as clean. (#3677)
  • 1.91.366.0 (2026-10-31): A partial gstack-post pr-body post keeps the PR’s intro. (#3683)
  • 1.91.365.0 (2026-10-31): An unclosed code fence in a second-model review no longer hides a later [P1] or not-ready verdict. (#3681)
  • 1.91.364.0 (2026-10-31): In /ship’s test check, --policy-from head now only adds test jobs, and a repository can set the per-process timeout. (#3676)
  • 1.91.363.0 (2026-10-31): A passing test job that leaves Bun’s .bun/ folder behind now counts as fresh, /ship’s PR-body count check no longer reads the Approvals table as a claim, and gstack-post pr-body drops a stale intro. (#3675)
  • 1.91.362.0 (2026-10-31): A /ship review pass on Capy is one call to a checked-in program, so reviewer briefs no longer pass through the model. (#3665)
  • 1.91.361.0 (2026-10-31): A reviewer’s install no longer rewrites another agent’s launch settings, and a hand-run gstack-upgrade on Capy no longer moves a checkout under another session. (#3673)
  • 1.91.359.0 (2026-10-31): New /verify skill: runs the repository’s own checks and the tests /ship would pick, fixes what breaks and repeats until green, then hands off to /ship. (#3672)
  • 1.91.358.0 (2026-10-31): Diffs that touch money, merge checks, auth or secrets now get one extra reviewer with a short brief for that kind of code, and /ship records whether it ran. (#3671)
  • 1.91.357.0 (2026-10-31): /ship’s test selection no longer flags a version-history table that the branch extended. (#3669)
  • 1.91.356.0 (2026-10-31): A reviewer’s install no longer upgrades a gstack checkout that other agents share. (#3667)
  • 1.91.355.0 (2026-10-31): /ship driven by another agent on Capy no longer spends one agent turn per finished reviewer, and it can count its own tool calls. (#3662)
  • 1.91.354.0 (2026-10-31): On Claude Code, /land-and-deploy loads about 15 KB less skill text per session. (#3663)
  • 1.91.353.0 (2026-10-31): /ship has a way through for repositories whose PRs never change VERSION (bump never), and an unattended /ship no longer writes a version bump nobody approved. (#3666)
  • 1.91.352.0 (2026-10-31): gstack’s model benchmarks can reach models through OpenRouter and now include particle-1, measured on gstack’s own tasks. (#3631)
  • 1.91.350.0 (2026-10-31): /ship’s review costs less and catches more: one batched specialist reviewer, the same blocking bar for both written reviews, and data files no code reads are reviewed as docs. (#3660)
  • 1.91.348.0 (2026-10-31): /ship’s test selection now links a test to the dotfiles it names, such as .gitleaks.toml or a CI workflow file, so a branch that changes only a dotfile runs that test instead of stopping with no test to run. (#3661)
  • 1.91.346.0 (2026-10-31): The sealed-files check now flags a home-folder path inside a shell default value (${VAR:-/home/<user>…}), as it already did in TypeScript. (#3569)
  • 1.91.345.0 (2026-10-31): A /ship run with a token cap on Capy spends fewer agent turns and counts only its own tokens, while every reviewer gets the same brief as before. (#3648)
  • 1.91.344.0 (2026-10-31): A PR that moves its changelog entry into changelog.d/ keeps its /ship review record. (#3656)
  • 1.91.341.0 (2026-10-30): gstack no longer leaves Ubicloud VMs running after the agent that started them dies: every VM has an owner and a 3-hour limit. (#3652)
  • 1.91.340.0 (2026-10-30): When several PRs merge as one batch, gstack counts a PR as merged only once GitHub reports it merged, instead of trusting its own record. (#3613)
  • 1.91.339.0 (2026-10-30): In batched merges, gstack can assign each PR’s version itself at merge, so nobody bumps versions by hand. (#3595)
  • 1.91.338.0 (2026-10-30): A waiver for the sealed-files check now counts only when it names the full commit SHA. (#3649)
  • 1.91.337.0 (2026-10-30): The plan-before-build rule for agent teams has two narrow exemptions, emergencies (a broken install or upgrade, a red main branch, a security bug) and fixes from an already diagnosed problem list; every other fix, one-line fixes included, gets a short engineering-only plan. (#3647)
  • 1.91.336.0 (2026-10-30): A repository can now assign its version when a PR merges instead of inside the PR: PRs include unversioned changelog entries, and gstack-ship-queue land assigns the version, pushes and merges. (#3594)
  • 1.91.335.0 (2026-10-30): Agent sessions on Capy that have no gstack checkout now read gstack’s working guide (factory.md) and the owner’s model preference from beside the skill, instead of silently skipping both. (#3643)
  • 1.91.334.0 (2026-10-30): OpenClaw opens gstack’s large task skills again. (#3610)
  • 1.91.333.0 (2026-10-30): gstack-factory-scorecard --now ends the measured window, so a past week no longer counts what happened after it. (#3635)
  • 1.91.332.0 (2026-10-30): gstack can remember which model you want your agents to use, and every Capy session reads a one-page summary of how gstack’s agents work together. (#3634)
  • 1.91.331.0 (2026-10-30): /ship and /review go back to the reviewers they used in 1.91.325.0, because the newer reviewers missed real blockers. (#3638)
  • 1.91.330.0 (2026-10-30): /ship reviewers now check a suspected defect against the code it depends on before they report it or let it go. (#3636)
  • 1.91.329.0 (2026-10-30): /ship’s test check now always runs the whole-repository guard tests on code changes, so they fail before review instead of in CI. (#3626)
  • 1.91.327.0 (2026-10-30): A new page (capy/README.md) shows how gstack and Capy run as a software factory, with measured numbers. (#3622)
  • 1.91.326.0 (2026-10-30): /ship reviewers now read one packet file each, and the parent reads a findings record of at most 60 lines instead of every reviewer’s transcript. (#3621)
  • 1.91.325.0 (2026-10-30): A /ship run with a token cap on Capy no longer hands off or stops just because the host’s own prompt is large, and a child run hands off instead of stopping. (#3620)
  • 1.91.324.0 (2026-10-29): A /ship token cap now estimates each step and reviewer from what the run has actually spent, so real caps stop refusing work that costs a fraction of the old guess. (#3614)
  • 1.91.323.0 (2026-10-29): After /ship fixes a blocking finding, a small fix (150 changed runtime lines or fewer) gets a focused second review of just the fix, by a fix reviewer, the Red Team and the adversarial pass, instead of every specialist again. (#3596)
  • 1.91.320.0 (2026-10-29): A branch that adds its own test job to /ship’s test policy now learns why it still fails, and gstack-post pr-body no longer keeps a stale copy of a section. (#3579)
  • 1.91.319.0 (2026-10-29): /ship’s sealed-files check no longer prints a line that reads like a push confirmation. (#3566)

For gstack contributors

  • 1.92.51.0: PRs no longer wait on the full Windows test suite: a short windows-smoke check is required and the full suite runs nightly on main. (#3806)
  • 1.92.39.0: A push to main no longer reruns the free tests on code its pull request already passed. (#3709)
  • 1.92.33.0: Eleven flaky tests fixed, and six more name their cause when they fail. (#3697)
  • 1.92.32.0: Four flaky tests fixed. (#3607)
  • 1.92.31.0: Nine flaky /ship eval cases fixed. (#3606)
  • 1.92.30.0: Free test shards finish closer together: slow test files are split and shards are planned from fresh timings. (#3585)
  • 1.92.21.0: CI uses blobless clones, and its history reads fail loudly instead of treating a failed fetch as missing. (#3713)
  • 1.92.4.0: gstack’s own batched merges take up to five ready PRs instead of three. (#3731)
  • 1.92.1.0: The free suite moves to ubicloud-standard-4 runners, because ubicloud-standard-2 made it too slow. (#3710)
  • 1.91.378.0: The /cso runtime image build passes again after Docker moved a tag it used. (#3699)
  • 1.91.370.0: The free suite runs on ubicloud-standard-2 instead of ubicloud-standard-8, at the same 20 shards, for about a quarter of the runner cost. (#3617)
  • 1.91.360.0: A PR’s changelog.d/ entry no longer triggers every paid eval case. (#3674)
  • 1.91.351.0: Four skill-eval check commands that gstack-evals uses as graders no longer pass runs that break their rule. (#3664)
  • 1.91.349.0: Nine flaky tests fixed. (#3646)
  • 1.91.347.0: The guide for coordinating agents says an agent archives only the threads it is responsible for. (#3657)
  • 1.91.343.0: The guide for coordinating agents asks the owner one decision per lettered line, with the options and a recommendation, so the owner can answer “do it” or a letter from a phone. (#3655)
  • 1.91.342.0: gstack’s own repository assigns versions at merge time: a PR adds a changelog.d/ entry instead of a version number. (#3654)
  • 1.91.328.0: Most PRs no longer pay for a separate paid eval run before their batch runs the same cases. (#3619)
  • 1.91.322.0: A PR’s paid eval run no longer covers every case just because a changed file is imported by all of them. (#3587)
  • 1.91.321.0: Free Tests passes again on Ubicloud runner image 20261026.1.0. (#3616)

ChatGPTNextWeb v2.16.0

minor PublishedFeb 16, 2025 SourceChatGPTNextWeb/ChatGPT-Next-Web Chinese translation

ChatGPTNextWeb v2.16.0

Highlights

  • New providers: DeepSeek and SiliconFlow — DeepSeek is promoted to a first-class ModelProvider (#5989) with its own DEEPSEEK_API_KEY / DEEPSEEK_URL settings (#6001, #6016), so you can run OpenAI and DeepSeek concurrently against different endpoints and keys instead of pointing an “OpenAI-compatible” slot at it. SiliconFlow arrives as another provider with model discovery, icons, VLM support, and a raised request timeout (#6141, #6185, #6190, #6193, #6194), plus the env vars needed for container deployments (#6168). Expect to re-check per-provider availability logic after upgrading — one such check already needed a fix for ByteDance models (#6134).

  • Reasoning traces become a first-class stream — This is the most consequential behavioral change: thinking content is streamed separately from the final answer. Initial DeepSeek streaming support (#6116, #6087) was generalized into three reasoning_content shapes plus parsing of <think></think> blocks out of SSE (#6204), covering deepseek-r1 on OpenAI-, Alibaba-, and ByteDance-style endpoints. o3-mini is added (#6121) but only via a self-described “temporary fix” (#6132), so treat it as provisional; o1 got a correctness fix (#5850) and knowledge-cutoff metadata (#6129). Verify your provider’s reasoning format is one of the handled variants, and expect reasoning to render as a distinct UI block.

  • Gemini 2.0 refresh, with a fix for truncated thinking output — The catalog is updated to gemini-2.0, gemini-exp-1206, and the flash-thinking experiments including the 01-21 variant (#5932, #5959, #6127, #6158). More important than the new IDs: #5965 fixes character loss in gemini-2.0-flash-thinking-exp-1219 responses and #5819 fixes Gemini summaries — if you saw silently truncated output, the upgrade is the remedy, not a config change.

  • Vision configuration finally works at runtime, including in Docker — Vision-capable model matching moved from build-time to runtime configuration (#5919), and #6010 fixes the long-standing bug where VISION_MODELS supplied at docker run was ignored. If you previously baked vision IDs into the image or worked around the dead env var, you can now configure it per deployment; the matching keywords also changed (#5815). Rendering gets SVG artifacts (#5816) and a fix for nested code blocks (#5827), plus friendlier scrolling (#5821).

  • MCP scaffolding lands as WIP; session isolation hardens — Initial Model Context Protocol support (#5974) is explicitly marked WIP and was followed by build-breaking omissions — a missing mcp_config.json required for builds (#6084) and a missing useMobileScreen import (#6075) — so source builders should confirm those files exist and avoid depending on MCP behavior being stable. On the stability side, forked sessions now get unique IDs to stop messages leaking between them (#6033), rerenders are keyed to the current session ID (#5812), a context-clear shortcut was added (#5468), and a model leak was closed (#5883).

  • Breaking changes — None noted in this release.

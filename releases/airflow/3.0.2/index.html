airflow 3.0.2

patch PublishedJun 10, 2025 Sourceapache/airflow Chinese translation

airflow 3.0.2

Highlights

  • Smoother Airflow 2 → 3 migration via compatibility shims — 3.0.2 restores compatibility shims with deprecation warnings for EmailOperator (#51004) and BaseNotifier (#50340), so legacy custom operators and notifiers keep importing after upgrade instead of hard-failing. Combined with the updated migration guide covering custom operators (#50871, #50948) and the revised upgrade path (#50318), this is a deliberate push to close the 2→3 gap. If you deferred a 3.0 upgrade because of custom operator breakage, this patch is worth re-evaluating.

  • Local testing now runs on the Task SDK execution path — dag.test (#50300, #50419), task.test (#50827), and ti.run (#50141) are all ported to the Task SDK, and airflow dags test can now run from local files (#50420). Local runs now exercise the same serialization/context machinery as production — better fidelity, but watch for behavior changes if your tests leaned on the old in-process path (e.g., deferred-task resumption in dag.test() was itself fixed in #51182).

  • Config keys relocated — audit your airflow.cfg — secret_key moves to the [api] section (#50839), and assorted webserver settings move into the fab provider (#50774, #50269, #50208, #50896). If you override these via config files or environment variables, update the section/key paths or the values will be silently ignored. The config command also drops an unnecessary “breaking” flag (#50781), making it easier to inspect the new layout.

  • Bundles added to sys.path — Both the task runner (#51318) and DAG processor (#50385) now prepend the bundle path to sys.path. This is the pragmatic fix that lets DAGs and tasks import custom packages shipped inside a bundle without manual PYTHONPATH plumbing — especially relevant for the airflow:3 Docker image or remote bundle providers.

  • Mapped-task and XCom correctness — LazyXComSequence gains slicing for filtering mapped-task items (#50117), XCom deserialization works with custom backends for mapped tasks (#50687), and upstream_mapped_index is handled correctly (#50641). Together with logical_date being populated properly in context vars (#50898) and plugin-defined macros working again in Airflow 3 (#50642, with macros relocated to the Task SDK execution_time module in #50940), this closes several data-plane gaps that could otherwise corrupt dynamic-task output.

  • API compatibility and processor stability hardening — The /run endpoint regains backward compatibility for older Task SDK clients, bulk API schemas are fixed for OpenAPI/client generation (#50852), variable endpoints accept keys containing slashes (#50841), and patch_task_instance now handles summaries and task groups (#50550). On the reliability front, a dag-processor memory leak (#50558), a task-supervisor CPU spike on heartbeat timeout (#51023), and SIGSEGV handling during DAG imports (#51171) are addressed — important if you run long-lived processors at scale.

No intentional breaking changes in this patch release.

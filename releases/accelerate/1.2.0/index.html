accelerate v1.2.0

minor PublishedDec 13, 2024 Sourcehuggingface/accelerate Chinese translation

accelerate v1.2.0

Highlights

  • Full TorchDynamo configuration — Accelerator now accepts dynamo_plugin=TorchDynamoPlugin(...), exposing the plugin’s full configuration beyond backend and mode shortcuts. Pass either dynamo_plugin or dynamo_backend; supplying both raises ValueError (#3251).
  • Opt-in device-map recovery — infer_auto_device_map(..., fallback_allocation=True) can place a smaller module when the default strategy would leave an accelerator unused under tight memory constraints. Existing behavior remains the default, while diagnostics now identify skipped devices and their minimum memory requirements (#3066).
  • Safer offloading and nested dispatch — get_state_dict_offloaded_model now materializes buffers on CPU, align_module_device only moves direct parameters, and get_state_dict_from_offload no longer relocates non-offloaded modules (#3217, #3253). preload_module_classes now reaches nested submodules, fixing meta-device failures during checkpoint dispatch (#3248).
  • Training-loop compatibility — DataLoaderShard.set_epoch() now forwards epochs to custom batch samplers implementing set_epoch(), enabling their epoch-dependent shuffling (#3246). DeepSpeed CPU offload selects matching CPU optimizers for AdamW, Adagrad, and 32-bit Lion instead of always using CPU Adam; other optimizer classes still fall back to CPU Adam. Wrapped schedule-free optimizers also now receive train()/eval() correctly (#3255, #3266).
  • Broader backend support — find_executable_batch_size recognizes XPU out-of-memory errors (#3236), safe deserialization uses numpy._core on NumPy 2 while retaining the NumPy 1 path (#3247), and 4-bit bitsandbytes models no longer require forced dispatch hooks with bitsandbytes ≥0.43.2, reducing overhead (#3223).
  • Breaking changes — None announced.
